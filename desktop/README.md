# 钥匙 · 电脑端

双击就进聊天。没有控制窗、没有浏览器地址栏、没有标签页 —— 一个窗口就是全部。

内部做了三件事：

1. 起一个本地 Web 服务，托管内嵌的聊天界面
2. 用 Edge / Chrome 的**应用模式**把界面装进一个独立窗口
3. 组播广播，让手机 App 自动发现这台电脑

关掉那个窗口，服务和进程一起退出。

## 打包（用你自己的 Builder）

### 第一步：生成带界面资源的单文件

```bash
cd "F:\AI Tool"
py desktop\embed_assets.py
```

输出 `desktop\keyapp_desktop_build.py`（155 KB，内含 16 个前端文件，压缩后 83 KB）。

> 为什么要这一步：Builder 调 PyInstaller 时不带 `--add-data`，
> 前端必须以数据形式写在 .py 里，否则 exe 里没有界面。

### 第二步：Builder 里这样填

| 项目 | 值 |
|---|---|
| 源文件 | `F:\AI Tool\desktop\keyapp_desktop_build.py` |
| 目标语言 | `Python` |
| 输出名称 | `钥匙` |
| 单文件 | ✅ 勾选 |
| 无控制台窗口 | ✅ **必须勾** |

产物是单个 `钥匙.exe`（约 12 MB）。

```
│ ☰  新建对话                          [正式] ＋│
│    未配置密钥 ▾                              │
├──────────────────────────────────────────────┤
│                                              │
│              聊天内容在这里                   │
│                                              │
├──────────────────────────────────────────────┤
│ 输入消息…                            ⚙ ☆ ＋  │

```

第一次打开会自动弹设置让你填 API Key。

### 手机怎么连

配对码在应用里面，不在别处：

**设置 → 连接 → 这台电脑**，最上面那张卡就是：

```
这台电脑                        电脑端
720454
http://192.168.1.49:8787 · 已配对 1 台设备
手机 App → 设置 → 连接，填这个配对码就能和这台电脑同步
```

手机端两种连法：

1. 打开手机上的「钥匙」App → 设置 → 连接 → 附近的电脑里点「用这台」→ 填那个 6 位码
2. 手机浏览器直接打开 `http://192.168.1.49:8787`

## 为什么用「应用模式」而不是内嵌 WebView

理想方案是把网页塞进 tkinter 窗口（pywebview）。实测被环境卡住了：

```
Exception: Qt plugin directory
'C:/Users/???/AppData/Local/Programs/Python/.../PyQt5/Qt5/plugins' does not exist!
```

用户名是非 ASCII（苗新田），PyInstaller 的 Qt 钩子解析这个路径时出错，
打包直接失败 —— 而 Builder 的命令行是固定的，塞不进 `--exclude-module`。

所以改用 Chromium 系浏览器的 `--app` 模式：

```
msedge.exe --app=http://127.0.0.1:8787 --window-size=1040,800
```

- 没有地址栏、没有标签页、没有书签栏
- 标题取页面标题，看着就是独立软件
- 零额外依赖，Windows 10/11 自带 Edge
- 用独立的 profile 目录（`keyapp-data/window-profile`），不碰你平时的浏览器

代价是任务管理器里会看到 msedge 子进程 —— 这一点和 Electron 类应用一样。

**没装 Edge / Chrome 时的兜底**：用系统默认浏览器打开，同时弹一个小窗显示配对码，
关掉小窗即退出。

## 数据放在哪

```
钥匙.exe 所在目录\
└── keyapp-data\
    ├── state.json         同步过来的对话与技能
    ├── tokens.json        已配对设备的令牌
    ├── files\             手机发来的文件
    └── window-profile\    窗口用的浏览器配置（可以删，会重建）
```

数据在 **exe 旁边**，不是 PyInstaller 的临时解压目录，换位置时连
`keyapp-data` 一起搬就行。

## 和手机的分工

| | 电脑端 | 手机 App |
|---|---|---|
| 提供界面 | 内置窗口 | 内置 WebView |
| 提供服务 | ✅ 主服务 | 只做客户端 |
| 对话 | 同步过来的副本 | 本机原件 |
| API Key | 各自独立，**不同步** | 各自独立 |

只有电脑端跑服务，手机是纯客户端，不常驻后台。

## 已知限制

- 必须同一个 WiFi；路由器开了 **AP 隔离**（访客网络常见）组播过不去
- 首次运行 Windows 会弹防火墙提示，要选「允许」
- 同步是**启动时 + 手动点**，不是实时推拉
- 同一对话两端同时改，按 `updatedAt` 取新，最后几百毫秒的改动可能丢
- 关掉窗口就退出；没有托盘常驻、没有开机自启（需要的话单独说）
- 令牌失效（电脑端数据被清过）时，手机端会提示「重新配对一次」

## 改完前端记得重新生成

```bash
cd "F:\AI Tool"
bun run sync                 # 前端 → www/
py desktop\embed_assets.py    # www/ → 内嵌进 build.py
```

不跑第二步，打出来的 exe 里还是旧界面。

## 开发时怎么跑（不打包）

```bash
cd "F:\AI Tool"
py desktop\keyapp_desktop.py    # 有 www 目录时直接读磁盘，改前端刷新即可
py desktop\selftest.py          # 25 项接口自测，不需要界面
```

`selftest.py` 会起临时端口走完配对 / 同步 / 冲突 / 墓碑 / 文件 / 发现，
跑完自动关掉。改服务端逻辑先跑它，比开窗口点快得多。
