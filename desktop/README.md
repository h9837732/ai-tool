# 钥匙 · 电脑端

一个窗口 + 一个本地服务。手机和电脑在同一个 WiFi 下就能互相同步对话、传文件。

## 打包（用你自己的 Builder）

### 第一步：生成带界面资源的单文件

```bash
cd "F:\AI Tool"
py desktop\embed_assets.py
```

输出 `desktop\keyapp_desktop_build.py`。
它把 `www/` 里的前端（16 个文件，压缩后 83 KB）内嵌成了 base64，
所以打出来的 exe 不需要任何外部文件。

> 为什么要这一步：Builder 调 PyInstaller 时不带 `--add-data`，
> 前端必须以数据形式写在 .py 里，否则 exe 里没有界面。

### 第二步：Builder 里这样填

| 项目 | 值 |
|---|---|
| 源文件 | `F:\AI Tool\desktop\keyapp_desktop_build.py` |
| 目标语言 | `Python` |
| 输出名称 | `钥匙` |
| 输出目录 | 自己选一个 |
| 单文件 | ✅ 勾选 |
| 无控制台窗口 | ✅ 勾选 |
| 图标 | 可留空 |

点「开始打包」，产物是单个 `钥匙.exe`（约 12 MB）。

## 打包后怎么用

双击 `钥匙.exe`：

```
┌────────────────────────────────────┐
│ 钥匙 · 电脑端          ● 运行中 :8787│
├────────────────────────────────────┤
│ 配对码                              │
│   422213     [复制] [换一个]         │
│ 手机 App →「设置 → 连接」→ 填这个码   │
├────────────────────────────────────┤
│ 访问地址                            │
│ http://192.168.1.49:8787 ← 手机填这个│
│ http://localhost:8787    ← 只在本机用│
│ 其他网卡（3 个，一般用不到）           │
├────────────────────────────────────┤
│ 附近的设备                   [刷新]  │
│ 共 1 台                             │
│ 我的手机        192.168.1.60:8787    │
├────────────────────────────────────┤
│ 日志                                │
│ 00:34:18  服务已启动                 │
│ 00:34:18  组播发现已启动             │
│ 00:34:32  发现设备：我的手机         │
├────────────────────────────────────┤
│ 设备名称 [电脑] [应用]  ☐开机自动启动  │
│ [停止服务] [打开界面] [数据目录]      │
└────────────────────────────────────┘
```

启动后会自动打开浏览器显示聊天界面。手机端：

1. **装好 App** →「设置 → 连接」→ 附近的电脑里点「用这台」→ 填配对码
2. 或者手机浏览器直接打开窗口里那个 `http://192.168.x.x:8787`

## 窗口上每个东西的作用

| 控件 | 作用 |
|---|---|
| 配对码 | 手机配对时填这个。每次启动随机换，只显示在这台电脑上 |
| 换一个 | 手动作废当前码（已经配对过的设备不受影响） |
| 地址 | 主网卡那个才是手机要用的，虚拟网卡的收起来了 |
| 附近的设备 | 组播发现到的其他钥匙设备，也会被手机 App 看到 |
| 设备名称 | 别人在「附近的电脑」里看到的名字 |
| 开机自动启动 | 往启动文件夹写一个 `.cmd`，登录后自动起服务 |
| 数据目录 | 打开 `keyapp-data`，里面有对话状态、令牌、收到的文件 |

## 数据放在哪

```
钥匙.exe 所在的目录\
└── keyapp-data\
    ├── state.json     同步过来的对话与技能
    ├── tokens.json    已配对设备的令牌
    └── files\         手机发来的文件
```

数据在 **exe 旁边**，不是 PyInstaller 的临时解压目录 —— 所以换位置时连
`keyapp-data` 一起搬就行。

## 和手机的分工

| | 电脑端 | 手机 App |
|---|---|---|
| 存放对话 | 同步过来的副本 | 原件（本机） |
| API Key | 各自独立，**不同步** | 各自独立 |
| 提供界面 | 浏览器打开 localhost | 内置 WebView |
| 提供服务 | ✅ 主服务 | 只做客户端 |
| 组播发现 | 广播 + 应答 | 通过连上的服务看邻居 |

只有电脑端跑服务，手机是纯客户端。这样手机不用常驻后台。

## 已知限制

- **必须同一个 WiFi**，跨网络不行
- **路由器开了 AP 隔离**时组播过不去，得手填地址
- 首次运行 Windows 会弹防火墙提示，要选「允许」
- 关掉窗口服务就停；不关窗口但锁屏不影响
- 同步是**启动时 + 手动点**，不是实时推拉
- 同一对话两端同时改，按 `updatedAt` 取新的，最后几百毫秒的改动可能丢

## 开发时怎么跑（不打包）

```bash
cd "F:\AI Tool"
py desktop\keyapp_desktop.py        # 有 www 目录时直接读磁盘，改前端不用重新生成
py desktop\selftest.py              # 25 项接口自测，不需要界面
```

`selftest.py` 会起一个临时端口走完配对/同步/文件/发现，跑完自动关掉。
改完服务端逻辑先跑它，比开界面点快得多。
